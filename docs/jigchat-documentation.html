1. Project Overview

JigChat V3 is a production-ready, full-stack real-time messaging web application. It supports one-on-one direct messaging, group chats with admin controls, live online presence, typing indicators, and message encryption at rest using AES-256-GCM.

CapabilityDetail
Messaging1-on-1 DMs and multi-user group chats
Real-timeSocket.IO — messages, typing, presence
EncryptionAll message content encrypted at rest (AES-256-GCM)
AuthJWT + Redis-backed sessions
PresenceRedis TTL keys with 30-second heartbeat
UIResponsive (desktop + mobile), Tailwind CSS + Radix UI

5.5 Security & Encryption

Password Storage
  bcryptjs · 12 rounds · one-way hash stored as password_hash

JWT Tokens
  Algorithm : HS256
  Expiry    : 7 days
  Validated : jwt.verify() + redis.get(`session:<id>`) must exist
  Logout    : DEL session:<id> in Redis → token immediately invalid

Message Encryption (AES-256-GCM)
  Key       : 32 bytes from ENCRYPTION_KEY env var
  IV        : 12 bytes (random per message)
  Auth tag  : 16 bytes
  Format    : "ENC:<iv_b64>:<tag_b64>:<ciphertext_b64>"
  Legacy    : Graceful fallback — plaintext returned if not ENC: prefixed

Socket Authentication
  JWT required in socket.handshake.auth.token before any events accepted

Group Authorization
  GroupMember.role = 'admin' | 'member'
  Admin-only: update group info, add member, remove other members
  Self: any member can remove themselves

6.4 Socket Hook (useSocket)

useSocket()  ← called once in ChatPage
  │
  ├── Creates singleton Socket.IO client (persists across re-renders)
  │   URL: VITE_SOCKET_URL
  │   Auth: { token } in handshake
  │   Reconnection: 5 attempts · 1s delay · websocket + polling
  │
  ├── On connect: emit join_room
  │
  ├── Heartbeat: emit join_room every 30 seconds
  │   (refreshes Redis online:<id> TTL before it expires at 90s)
  │
  ├── Inbound event handlers:
  │   receive_message        → addMessage() · markAsRead() · bumpUserToTop()
  │   receive_group_message  → addGroupMessage() · bumpGroupLastMessage()
  │   message_deleted        → removeMessage()
  │   member_added           → addGroupLocally() · join socket room
  │   member_removed         → removeGroupLocally()
  │   group_member_removed   → removeMemberLocally() · update selectedGroup
  │   user_online            → updateUserStatus(id, true)
  │   user_offline           → updateUserStatus(id, false, lastSeen)
  │   user_typing            → updateUserTypingStatus(id, true)
  │   user_stop_typing       → updateUserTypingStatus(id, false)
  │
  └── Outbound helpers:
      sendMessage(receiverId, content)      → emit send_message
      sendGroupMessage(groupId, content)    → emit send_group_message
      emitTyping(receiverId)                → emit typing (auto-stop 2s)
      emitStopTyping(receiverId)            → emit stop_typing

7. Workflow Diagrams

7.1 Authentication Flow

Browser opens app
        │
        ▼
  authStore.isAuthenticated?
  ├── true  ──────────────────────────► /chat
  └── false ──► /login
                    │  enter email + password
                    ▼
              POST /api/auth/login
                    │
                    ▼
              Server:
              1. SELECT user WHERE email = ?
              2. bcrypt.compare(password, passwordHash)
              3. jwt.sign({ userId }, JWT_SECRET, { expiresIn: '7d' })
              4. redis.set(`session:${id}`, token, 'EX', 604800)
                    │
                    ▼  { user, token }
              authStore.login(user, token)
              ── persisted to localStorage ──
                    │
                    ▼
              navigate → /chat

7.2 Direct Message Flow

User A selects User B
        │
        ▼
GET /api/messages/:A/:B  →  messages[] in chatStore
        │
        ▼
User A types
  ├── emit "typing" → server → emit "user_typing" to B
  └── auto emit "stop_typing" after 2 seconds of no keys
        │
        ▼
User A presses Enter
        │
emit "send_message" { senderId:A, receiverId:B, content }
        │
        ▼
  Server:
  1. AES-256-GCM encrypt content
  2. INSERT into messages
  3. Un-hide contact if previously hidden
  4. emit "receive_message" → User A + User B
        │
  ┌─────┴─────┐
  ▼           ▼
User A      User B
addMessage()  └── Active chat with A?
                  ├── YES → addMessage() + POST mark-read
                  └── NO  → incrementUnreadCount(A)
                            bumpUserToTop(A)

7.3 Group Message Flow

Admin creates group
  POST /api/groups { name, memberIds }
        │ creates GroupMember rows (creator = admin)
        │
  emit "join_group_room" groupId
        │ all members socket.join("group:<id>")
        │
        ▼
Member sends message
  emit "send_group_message" { senderId, groupId, content }
        │
        ▼
  Server:
  1. Verify sender is GroupMember
  2. AES-256-GCM encrypt
  3. INSERT into messages
  4. emit "receive_group_message" to room "group:<id>"
        │
        ▼
All room members receive:
  ├── Active in group → addGroupMessage()
  └── Elsewhere      → incrementGroupUnreadCount()
                       bumpGroupLastMessage()

7.4 Online Presence Flow

Socket connects
        │ emit "join_room"
        ▼
  Server:
  redis.set(`online:${id}`, "1", "EX", 90)
  socket.join all group rooms
  emit "user_online" id → all sockets

  ─── every 30 seconds ───────────────
  Client re-emits "join_room"
  Server: redis.set(`online:${id}`, "1", "EX", 90)   ← refresh TTL

  ─── on disconnect ──────────────────
  Server:
  redis.del(`online:${id}`)
  UPDATE users SET lastSeen = now() WHERE id = ?
  emit "user_offline" { id, lastSeen } → all sockets

All clients: updateUserStatus(id, false, lastSeen)
